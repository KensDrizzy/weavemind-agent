- `BrowserGuard` 敏感页面保护

### 调研对照

[chrome-devtools-mcp 官方文档](https://github.com/ChromeDevTools/chrome-devtools-mcp) 推荐首选项为 `--browserUrl http://127.0.0.1:<port>`（早于 `--wsEndpoint`），优点：
- 不需要解析 `DevToolsActivePort` 里的 WS 路径
- 与扩展程序兼容
- 配置更简单

### 升级动作（[mcp_client/manager.py:switch_to_shared](mcp_client/manager.py:289)）

把原来的"二选一 → 单点回退"改成 **顺序回退链**：

```
1) --browserUrl http://127.0.0.1:<port>    （官方首选）
2) --wsEndpoint ws://127.0.0.1:<port><path>（保留作为兜底）
3) --autoConnect --userDataDir <dir>       （DevToolsActivePort 缺失）
4) --autoConnect                           （兜底）
```

任一步失败由 `_restart_chrome_server` 触发回滚，外层顺序尝试下一步；全部失败时记录最后一次错误。

## 6. 亮点 5：代码 RAG

### 当前实现（成立）

- `PythonASTChunker` AST 分块（import / 类概览 / 方法 / 函数），语法错误回退行级 `FallbackChunker`
- Chroma 向量库 + SQLite FTS5（bm25 排序）双索引
- `QueryRewriter`（规则/auto/llm）扩展查询意图
- 混合检索：`semantic*0.5 + keyword*0.3 + type_boost + dual_hit_bonus`
- `ResultReranker`（heuristic / cross_encoder / llm）
- `SearchCache`（TTL+LRU，索引指纹失效）
- 增量同步：mtime 快筛 + MD5 精确确认

### 调研对照

主流混合检索系统（OpenSearch / Elasticsearch / Azure AI Search / MongoDB Atlas / Weaviate / LangChain `EnsembleRetriever`）的默认融合方式都是 **RRF (Reciprocal Rank Fusion)**：
- 公式：`score = Σ 1/(k + rank_i)`，典型 `k=60`
- 优点：**不需要分数归一化** —— 对 BM25/cosine 量纲差异天然鲁棒，加权求和则需要谨慎调权重

### 升级动作（[rag/pipeline.py:_hybrid_search](rag/pipeline.py:411)）

- 抽出 `_weighted_fuse`（原公式，**保持默认**，向后兼容）和 `_rrf_fuse`（新增）
- 由 `rag.retrieval.fusion` 配置切换；RRF 的 k 通过 `rag.retrieval.rrf_k`（默认 60）调整
- RRF 主分数之上仍叠加少量类型/双命中加成，保留对 function/method 代码段的偏好
- `config.yaml.example` 增加注释样例

### 新增测试（[tests/test_rag_fusion.py](tests/test_rag_fusion.py)）

- `test_weighted_fuse_matches_original_formula`：原公式精确等值
- `test_rrf_fuse_uses_rank_reciprocal`：RRF 得分 = `1/(60+rank+1)` 之和（含类型/双命中加成）
- `test_hybrid_search_respects_fusion_config`：配置项可正确切换分支

### 10.1 LLM 切换到 DeepSeek-v4-flash

**背景**：DeepSeek 官方现已提供 OpenAI / Anthropic 双兼容入口，模型矩阵更新为
`deepseek-v4-flash` / `deepseek-v4-pro`；旧名 `deepseek-chat` / `deepseek-reasoner`
将于 2026/07/24 弃用，二者分别对应 v4-flash 的非思考与思考模式。

**修改**（`config.yaml`，本机不入库）：

```yaml
llm:
  provider: deepseek
  model: deepseek-v4-flash         # 由 deepseek-v4-pro 改为 flash（成本/延迟更优）
  max_tokens: 8192
  temperature: 0

providers:
  deepseek:
    base_url: https://api.deepseek.com/anthropic   # Anthropic 兼容入口
    api_key_env: DEEPSEEK_API_KEY
    default_model: deepseek-v4-flash
```

**验证点**：
- `core/llm_factory.create_llm("deepseek", "deepseek-v4-flash")` 在 Anthropic 兼容
  入口下走的是 `ChatAnthropic(base_url=...)`，因此 `bind_tools` / `with_structured_output`
  与 Supervisor 升级后的"结构化路由"完全兼容。
- `team.classifier_*` 仍维持 deepseek-v4-pro，便于复杂度分类用更稳的模型。
- `api_key_env` 字段在 WeaveMind 的语义是"环境变量名"，应填写
  `DEEPSEEK_API_KEY` 等环境变量名，避免 key 落盘。

### 10.2 MCP chrome-devtools 连接失败的双层根因

启动时 CLI 持续报：

```
[mcp_client.manager] WARNING: MCP Server 'chrome-devtools' 连接失败
[mcp_client.manager] WARNING: 没有可用的 MCP Server
[asyncio] ERROR: RuntimeError('Attempted to exit cancel scope in a different task ...')
```

**排查过程**：

| 步骤 | 动作 | 发现 |
| --- | --- | --- |
| 1 | 用 `MCPConnection` 复刻连接，打出 `_last_error` | 真实错误是 **`Connection closed`**（子进程握手前就退出） |
| 2 | 用 mcp 库原样握手 + `errlog=sys.stderr` 不吞输出 | 子进程能打印 banner，**握手成功**，工具数 29 |
| 3 | 比较两次的差异 | 仅 `_merge_env()` 注入的 `PATH` 不同 |
| 4 | 锁定 PATH 变量 | 配置里 `PATH: /opt/homebrew/bin:/usr/local/bin:${PATH}` 把 `/usr/local/bin` 顶到前面 |
| 5 | 验证 `/usr/local/bin/node --version` | **v20.16.0**，差 0.03 不达标 |
| 6 | 查 chrome-devtools-mcp 引擎要求 | `node ^20.19.0 \|\| ^22.12.0 \|\| >=23` |

**结论：两层叠加问题**

| # | 原因 | 现象 | 修复 |
| --- | --- | --- | --- |
| 1 | `~/.npmrc` 指向私有镜像 `registry-npm.xiaoyuanhao.com`，对 chrome-devtools-mcp 返回 **403** | npx 根本拉不到包 | 在 MCP 子进程 env 注入 `npm_config_registry: https://registry.npmjs.org/`，仅作用于此 server，不污染全局 npm |
| 2 | 注入的 `PATH` 把 `/usr/local/bin` 排在前面，那里的 `node` 是 **v20.16.0**，包的 `engines` 校验不过 | npx 启动 chrome-devtools-mcp 子进程立即退出 → MCP 握手收到 `Connection closed` | `PATH` 头部追加 `/opt/homebrew/opt/node@22/bin`，强制使用 v22.22.3 |

**最终修复后 `mcp.servers.chrome-devtools.env`**（`config.yaml`）：

```yaml
env:
  # node@22 (v22.x) 必须排在最前：chrome-devtools-mcp 要求 node ^20.19 || ^22.12 || >=23，
  # /usr/local/bin/node 是 v20.16.0（不达标）；让它排前面 → engines 校验失败 → 子进程秒退。
  PATH: "/opt/homebrew/opt/node@22/bin:/opt/homebrew/bin:/usr/local/bin:${PATH}"
  # 本机 ~/.npmrc 指向私有镜像，对 chrome-devtools-mcp 返回 403。
  # 仅为此 MCP 子进程覆盖为官方 registry，不影响全局 npm 配置。
  npm_config_registry: "https://registry.npmjs.org/"
```

**端到端验证**（走 `MCPConnection.connect()` 原路径，未绕过任何代码）：

```
配置 PATH 头: /opt/homebrew/opt/node@22/bin:/opt/homebrew/bin:/usr/lo...
MCPConnection 连接结果: True
工具数: 29 | 示例: ['click', 'close_page', 'drag', 'emulate']
```

| 截图里红色的 `RuntimeError('Attempted to exit cancel scope in a different task ...')` | MCP stdio 连接失败后，anyio TaskGroup 在 `asyncio.run` 清理阶段的次生噪音 | 该错误**不致命**，是握手失败的副产物；连接成功后即消失。可在 `_connect_stdio` 失败分支显式 `cancel` 当前任务再让外层退出，消除红色 traceback 噪音 |
